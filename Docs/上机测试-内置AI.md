# 上机测试：内置 AI 与日志块

按顺序做，每一步都有明确的"看到什么算通过"。全程不需要改代码。

## 0. 准备

1. 关掉旧版 BGI（含托盘残留），用新的 `dist/BetterGI` 整个目录替换，不要只换 exe
2. 启动后选截图方式，先确认能正常抓帧（遮罩窗口里有画面）
3. **任务设置 → AI 智能决策（内置）**，填四项：协议、服务地址、模型名、密钥
   - OpenAI 兼容填到 `/v1`，例如 `https://api.deepseek.com/v1`
   - 模型必须支持工具调用，`deepseek-chat` / `qwen-max` / `glm-4-plus` 都可以
4. 其余保持默认：启用、跑图卡死接管、6 步、45 秒、允许传送、记录决策日志

> 建议第一次测试把「附带截图」**关着**。开着时每步多 1500–2000 token，且只有多模态模型认。

## 1. 连通性测试（30 秒）

点卡片底部「发送测试请求」。

**通过**：按钮下方显示「连接正常：可用」，日志里出现

```
[AI] · 连通性测试 · 812ms · 可用
```

**不通过**：

| 日志/界面 | 原因 | 处理 |
|---|---|---|
| `401` / `invalid api key` | 密钥错或没生效 | 重新粘贴，注意别带空格 |
| `404` | 地址少了或多了 `/v1` | 对照服务商文档改地址 |
| `400 ... tools` | 模型不支持工具调用 | 换模型，别用纯对话模型 |
| `连接超时` | 网络或本地服务没起 | 本机 Ollama 先 `ollama serve` |

连通性测试**不占预算**，可以反复点。

## 2. 卡死接管（核心）

挑一条以前卡过的路线，越容易卡越好（山体边缘、洞口、空气墙附近）。

**触发条件**：连续 8 帧位移 < 3 米，且这是同一段的第 3 次卡死。前两次仍走原有的规则脱困（松 W → 下落 → 普攻 → 左右平移），第 3 次才交给模型。

**预期日志**：一整块，形如

```
[AI] ┌ 接管 #1 · 规则脱困连续 3 次无效 · 距目标 82m
[AI] │ 位置 (1234.5, 567.8) · 距目标 82.3m · 地面站立/奔跑
[AI] │ 目标 (1200.0, 520.0) · 预算 6 步 / 45s · 本次已用 3/300 · 模型 deepseek-chat
[AI] │ 任务 《追击》· 击败所有魔物 · 进度 2/4 · 目标距离 156m
[AI] │ [1/6] move forward 600ms → 拉近 6.2m
[AI] │ [2/6] turn +120 → 无进展
[AI] │ [3/6] jump → 无进展
[AI] │ [4/6] move backward 400ms → 拉近 2.1m
[AI] │ [5/6] move left 800ms → 拉近 9.4m
[AI] └ 成功 · 已到达目标点 · 5 步 / 5 请求 / 21.3s · 82.3 → 3.8m
[AI] → 交还规则逻辑，继续本段路线
```

**判定**：

| 看到 | 说明 |
|---|---|
| 块头有坐标、距离、模型名 | 感知与配置都通了 |
| 每步后面有「拉近 / 后退 / 无进展」 | 坐标在实时更新，不是模型自述 |
| 块尾「x 步 / y 请求」 | 实际消耗；步数少于请求数说明有一步只说话没动手 |
| 收尾 `→ 交还规则逻辑` | 成功或拉近了 ≥5m，路线继续 |
| 收尾 `→ 未奏效，按原逻辑重试或放弃` | 模型没救回来，走了官方逻辑 |

## 2.5 任务进度识别

挑一个**正在追踪的任务**做，最好带计数（`0/3`）或距离（`120m`）。任务面板在左上角，被其他 UI 挡住时读不到。

先确认读得对：接管块头应出现一行

```
[AI] │ 任务 《任务名》· 当前步骤原文 · 进度 2/4 · 目标距离 82m
```

字段对不上时的排查：

| 现象 | 原因 |
|---|---|
| 显示「任务面板为空」 | 没追踪任务、面板被挡、或 UI 缩放导致区域偏了 |
| 任务名识别成了步骤 | 面板里没有明显的字号差异，退化成首行即标题 |
| 没有计数 / 没有距离 | 面板文字里本来就没有，属于正常 |
| 步骤里出现乱码 | OCR 识别问题，与 AI 无关，看日志里的原文 |

**推进判定**：走到任务节点交互（对话、开启、拾取）后，块里应出现

```
[AI] │ 任务推进 · 收集 2/3 → 3/3
```

如果连续几步都不出现「任务推进」，但距离在缩短，说明只是绕路脱困，属于正常。

关掉「识别任务进度」后，块头不再有 `任务` 行，模型也拿不到任务面板内容。

## 3. 三个开关的验证

| 操作 | 预期 |
|---|---|
| 关掉「记录决策日志」 | 块内每步消失，块头、块尾仍在 |
| 关掉「跑图卡死接管」 | 第 3 次卡死直接按官方逻辑放弃，日志里没有块 |
| 关掉总开关「启用内置 AI」 | 不抓帧、不发请求，日志写 `[AI] 跳过接管：总开关未启用` |
| 把「单次接管步数」改成 1 | 块里只有 `[1/1]`，块尾写「步数用尽」 |
| 把「允许传送」关掉 | 距离 80m 以上时模型不应调用 `tp`，只能走位 |

## 3.5 本地助手（可选）

侧边栏「AI 助手」页，先把「启用本地助手」打开。测试时建议**关掉**「沙箱内写入免确认」，这样每一步都会弹窗，能看清模型到底想干什么。

| 任务输入 | 预期 |
|---|---|
| `列出当前目录，告诉我有哪些子目录` | 直接执行，不弹窗；日志 `[1/..] list_dir . → ...` |
| `在 User 目录下新建 test-agent.txt，内容写 hello` | 关掉免确认时应弹一次授权；允许后写入成功 |
| `读一下 C:\Windows\win.ini 前 20 行` | 必定弹窗（沙箱外），点「否」后模型应换方案或结束，**不应重复申请同一路径** |
| `运行 cmd.exe /c echo hi` | 沙箱外 + 可执行文件，应弹窗；拒绝后任务正常收尾 |
| 把步数改成 1，随便下一个两步才能完成的任务 | 块尾写「达到步数上限」，不应无限循环 |

判定要点：

- 授权弹窗里的路径必须是完整绝对路径，不能只写「User」这种相对名
- 点「否」之后日志应出现 `[AI] │ 授权 ... 拒绝 ...`，随后模型不能原地重试
- 关掉「启用本地助手」后，点执行应立刻返回「本地助手未启用」，不发任何请求

## 4. 预算与熔断（可选，但建议看一眼）

- 每小时 60 次、每次运行 300 次，两个上限任一触顶都会拒绝请求，日志写 `已达每小时上限`
- 连续 3 次请求失败 → 冷却 2 分钟，日志写 `内置 AI 连续失败 3 次，冷却 120 秒`
- 想快速触发：把服务地址改成 `https://127.0.0.1:1/v1`，跑一次卡死即可

## 5. 日志在哪

- 遮罩窗口：连续的行就是一块，块与块之间有空行
- 文件：安装目录下 `log/better-genshin-impact<日期>.log`
- 筛全部 AI 记录：搜 `[AI]`；只筛接管：搜 `[AI] ┌`

## 6. 出问题时要抓的三样东西

1. 那一整块 `[AI]` 日志（从 `┌` 到 `└`，不要只截一行）
2. 当时的游戏截图（能看到角色卡在什么地形）
3. 设置页截图（模型名与地址，**密钥打码**）

有这三样就能判断是"模型决策不对"还是"感知不准"，这两个方向的修法完全不同。
