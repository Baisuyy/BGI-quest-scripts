# 内置 AI 决策（特别版）

这不是脚本，也不是外挂进程。特别版在 BGI 内核里加了一层大模型能力：**BGI 自己收集状态、自己问模型、自己执行动作**。
模型不读内存、不做图像识别，只回答「现在该往哪走、按什么键」，感知与执行全部复用 BGI 已有的能力。

> 一句话：官方脱困是一套固定动作，特别版在固定动作失效后，把方向盘交给模型几秒钟。

## 1. 为什么要内置

官方 `TrapEscaper` 的脱困逻辑是写死的：

1. 松 W、下落、普攻
2. 左/右平移 700–1000ms，角度随机偏 30–45°
3. 重复上述步骤，同时逐步加大偏角，凑出「转一圈」的效果
4. 同一段路线卡死 3 次 → `RetryException`，整条路线重试或放弃

这套逻辑能处理大多数「撞到石头」，但处理不了**空气墙、夹缝、错层、传送点落在障碍物里**这类情况——
因为它的动作集合里没有「换一条路」这个选项，只会原地把同一套动作做得更用力。

模型的作用不是替代寻路，而是在规则失效的那几秒里，根据**坐标有没有变化**换策略：
后退多少、往哪边绕、要不要跳、要不要干脆传送。

## 2. 一次接管发生了什么

```
PathExecutor 检测到连续 8 帧位移 < 3 米（第 3 次）
        │
        ├─ 释放所有按键，抓一帧画面
        ├─ 地图匹配 → 当前坐标；Bv → 运动状态；OCR → 任务面板文字
        ├─ 组装 system prompt + 首条 user 消息（坐标 / 目标 / 距离 / 状态）
        │
        └─ 循环（最多 N 步，总时长 M 秒）
             模型返回一个工具调用
                   ↓
             BGI 执行（WASD / 跳跃 / 普攻 / 交互 / 传送 / 开关功能）
                   ↓
             再抓一帧 → 新坐标 → 作为工具结果回填
                   ↓
             距离 < 4 米 → finish；否则继续
```

结束条件：到达目标、模型调用 `finish`、步数用尽、总超时。
结束后无论成败都释放按键、撤销模型开过的功能开关，然后**交还规则逻辑**：
成功（到达，或拉近 ≥ 5 米）就清零卡死计数继续跑原路线，失败就按官方逻辑放弃。

## 3. 模型能用的工具

工具由 BGI 提供，模型只能选、不能自己发明。全部走 BGI 的输入通道，和手按键盘没有区别。

| 工具 | 参数 | 说明 |
|---|---|---|
| `move` | `direction`(forward/backward/left/right)、`ms`(100–2000) | 朝一个方向移动一小段 |
| `turn` | `dx`(-600–600) | 横向转镜头，像素 |
| `jump` | — | 跳跃，跨矮障碍 |
| `attack` | — | 普攻，打碎挡路物件 |
| `interact` | — | F 键交互/拾取 |
| `tp` | — | 传送到接管目标点，仅距离 > 80 米且允许时可用 |
| `toggle_feature` | `feature`(auto_skip/auto_pick/auto_eat)、`enabled` | 临时开关 BGI 自带触发器，接管结束自动撤销 |
| `finish` | `success`、`reason` | 结束接管 |

`tp` 与 `toggle_feature` 都有硬约束：距离不够不给传送，功能名不在白名单直接拒绝。
模型改不了配置、读不到密钥、也调不了脚本。

## 4. 感知为什么便宜

| 输入方式 | 每次决策的 token |
|---|---|
| 结构化状态（坐标、距离、运动状态、任务文字） | 约 200–400 |
| 768px 压缩截图（`VisionMode`） | 约 1500–2000 visual token |

坐标来自地图匹配，比让模型「看图估位置」准得多，所以**默认只发结构**。
只有纯文本判断不出地形（例如大世界解谜、明显的高低差）时，才建议打开截图模式。

## 5. 刹车：不会把额度烧光

| 机制 | 默认值 | 说明 |
|---|---|---|
| 触发条件 | 第 3 次卡死 | 前两次仍由 `TrapEscaper` 处理，模型不参与 |
| 单次步数 | 6 步 | 一步一次工具调用 |
| 单次超时 | 45 秒 | 到点强制停止 |
| 每小时上限 | 60 次 | 滚动一小时，内置与脚本共用 |
| 每次运行上限 | 300 次 | 重启 BGI 清零 |
| 熔断 | 连续失败 3 次 → 冷却 2 分钟 | 服务挂掉时不会反复重试 |
| 有效判定 | 拉近 ≥ 5 米 | 原地动一下不算成功 |

按 6 步算，一次失败接管大约 7 次请求（6 次决策 + 1 次收尾）。
DeepSeek 这类模型单次几厘钱，**一条卡死的路线通常几毛钱以内**；本地 Ollama 则是零成本。

## 6. 配置项

**任务设置 → AI 智能决策（内置）**

| 配置 | 默认 | 建议 |
|---|---|---|
| 启用内置 AI | 关 | 填好地址与模型后打开 |
| 服务协议 | OpenAI 兼容 | Claude 选 Anthropic |
| 服务地址 | `https://api.deepseek.com/v1` | OpenAI 兼容填到 `/v1`；本机 Ollama `http://127.0.0.1:11434/v1` |
| 模型名 | `deepseek-chat` | 必须支持 function calling，见下 |
| 服务密钥 | 空 | 本机回环地址可留空 |
| 跑图卡死接管 | 开 | 关掉就退回官方逻辑 |
| 允许接管时传送 | 开 | 怕传送打乱路线就关掉 |
| 单次接管步数 | 6 | 复杂地形可到 8–10，越高越贵 |
| 单次接管超时 | 45 秒 | 本地大模型加载慢可到 90 |
| 附带截图 | 关 | 只在纯文本判断不准时开 |
| 每小时/每次运行上限 | 60 / 300 | 按预算调 |
| 采样温度 | 0.2 | 决策类不要超过 0.5 |
| 记录决策日志 | 开 | 关掉只是不写日志，审计记录仍保留 |

卡片底部的「发送测试请求」会用当前配置发一条最小请求，**不占额度、不参与熔断**，用来确认地址、密钥、模型名是否可用。

### 支持工具调用的模型（经验值）

| 服务 | 可用模型 |
|---|---|
| DeepSeek | `deepseek-chat` |
| 通义千问 | `qwen-max`、`qwen-plus` |
| 智谱 | `glm-4-plus`、`glm-4-air` |
| Moonshot | `moonshot-v1-8k` 及以上 |
| 硅基流动 | `Qwen/Qwen2.5-72B-Instruct` 等 |
| 本机 Ollama | `qwen2.5:7b` 及以上（`ollama pull qwen2.5:7b`） |
| Anthropic | `claude-sonnet-4-5` 等 |

纯对话模型（`*-chat` 但不支持 tools 的旧模型）会在第一次决策时报 400，日志里能直接看到。

## 7. 日志：一次接管一块

一次接管在日志里是一整块，每条都带 `[AI]` 前缀：

```
[AI] ┌ 接管 #1 · 规则脱困连续 3 次无效 · 距目标 82m
[AI] │ 位置 (1234.5, 567.8) · 距目标 82.3m · 地面站立/奔跑
[AI] │ 目标 (1200.0, 520.0) · 预算 6 步 / 45s · 本次已用 12/300 · 模型 deepseek-chat
[AI] │ 任务面板：追击 156m
[AI] │ [1/6] move forward 600ms → 拉近 6.2m
[AI] │ [2/6] turn +120 → 无进展
[AI] │ [3/6] jump → 无进展
[AI] │ [4/6] move backward 400ms → 拉近 2.1m
[AI] │ [5/6] move left 800ms → 拉近 9.4m
[AI] └ 成功 · 已到达目标点 · 5 步 / 5 请求 / 21.3s · 82.3 → 3.8m
```

怎么读：

| 位置 | 含义 |
|---|---|
| 块头 `Warning` 级 | 日志级别调到 Warning 也能看到「接管开始了」 |
| `拉近 / 后退 / 无进展` | 相邻两帧的坐标差，不是模型自述 |
| `5 步 / 5 请求` | 实际消耗；步数少于请求数说明有一步只说话没动手，或请求失败重试 |
| 块尾 `82.3 → 3.8m` | 起点到终点的直线距离 |

关掉「记录决策日志」后，块内每步不再输出，块头与块尾保留——排查时至少知道接管过几次、成没成。

脚本 `ai.Chat()` 不占块，只写单行：

```
[AI] · 脚本问答 · 812ms · 调用 move
```

日志位置：

- 遮罩窗口：连续的行就是一块，块与块之间用空行隔开
- 文件：安装目录下 `log/better-genshin-impact<日期>.log`，搜 `[AI]` 可筛出全部接管记录

## 8. 失败时会怎样

所有失败都被收敛成「这一次接管没成功」，不会中断任务：

| 情况 | 行为 |
|---|---|
| 未启用 / 未配置模型 | 直接跳过，不抓帧不请求 |
| 超预算 / 冷却中 | 写一条 `Information` 日志，按官方逻辑放弃本段 |
| 请求超时 | 记一次失败，交还规则逻辑 |
| 模型返回 400/401/403 | 记一次失败并写进日志与审计，冷却计数 +1 |
| 模型调用不存在的工具 | 工具结果里返回可用工具列表，让它重选 |
| 模型只说话不动手 | 催一次，仍然不动就结束接管 |

无论走哪条路，`PathExecutor` 原有的「3 次卡死 → 重试/放弃」逻辑都还在，只是多了一次机会。

## 9. 和脚本 `ai.Chat()` 的关系

两者共用同一个内核、同一份配置、同一套预算：

```
        ┌──────────────┐
脚本 ──▶│  AiAgentHost │──┐
        └──────────────┘  │
                          ├──▶ AiKernel（密钥/预算/熔断/审计）──▶ LLM
        ┌──────────────┐  │
内置 ──▶│  AiOperator  │──┘
        └──────────────┘
```

- 脚本拿到的是只读属性 + `Chat()`，读不到 apiKey，也绕不过预算
- 内置决策走工具循环，脚本那边完全不感知
- 设置页改一次，两边同时生效；不会出现「脚本能跑、内置跑不了」的配置漂移

## 11. 已知边界

- **没有视觉避障**：模型看不到 3D 地形，只能根据「走了多远」推断；它不会预判前方有坑
- **不替代寻路**：长距离仍靠路线的录制点位，模型只在卡死时救火
- **地图匹配失败时**：坐标读不到会沿用上一次有效值，连续失败时接管会主动结束，避免瞎走
- **战斗不在范围内**：接管期间只做移动与交互，不打怪；需要战斗时由原有逻辑切回
- **传送会重置路线状态**：开启传送后，落点可能偏离路线，接管结束时若距离仍远，按失败处理
