# 全局搜索

标题栏上一条输入框，回车把结果摊到独立页面里。解决的是「知道有这功能但找不到入口」：以前找任务要先进「独立任务」再认清分组，找脚本要进「全自动」再挑配置组。

## 交互

```
标题栏输入 → 回车 → 导航到「搜索结果」页（按页面 / 独立任务 / 脚本分组）
              ↓ 点击任一条
           跳到它所属的页面
```

- `Ctrl+K` 聚焦搜索框，`Esc` 清空。
- 搜索框放在 `TitleBar.Header` 里、标题的拖拽行为之外，点它不会变成拖窗口。
- Header 是 Auto 宽度，所以用横向 `StackPanel` 排，不用 `Grid`（`*` 列会拿到 0，搜索框被压没）。

## 索引来源

| 类别 | 来源 | 说明 |
|---|---|---|
| 页面 | `GlobalSearchService.Pages` 常量表 | 22 个导航页 + 别名。别名写用户会输的词（「日志」「遮罩」「代理」「抽卡」），不是标题变体 |
| 独立任务 | `SoloTaskRegistry.All` | 显示名 + 分组 + 用途说明，`TaskId` 作关键字 |
| 脚本 | `User\ScriptGroup\*.json` | 配置组名与组内脚本名，30 秒缓存 |

不做倒排索引：任务在内存里，脚本目录一般几十个文件，现扫够快；建索引反而多出「改了文件索引没刷新」的不一致。

## 匹配规则

- 空格分隔的多个词是 **AND**：搜「自动 演奏」不会把「自动任务」算进来。
- 打分：标题完全相等 1000 / 前缀 800 / 包含 600 / 别名或副标题包含 300，再减标题长度（短标题更可能是目标）。
- 单次最多 80 条，超了说明该把关键词写具体。

## 已知边界

- 命中的是**页面**，不是页面里的某个控件。搜「日志」落到「设置」页，还需要自己滚到日志那一组——做控件级锚点要给每个设置项登记定位信息，维护成本远高于收益。
- 脚本条目只负责把你送到「全自动」页，不会自动选中那个配置组（`ScriptControlViewModel` 目前没有接受外部选择的入口）。
