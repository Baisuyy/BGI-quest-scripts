# 远程任务（QQ 机器人）

在 QQ 里给机器人发一句「一条龙」，BetterGI 就开跑，跑完把结果发回来；失败时附一张当时的画面。想升级也可以在这里发「更新」。整条链路只用一个出站长连接，家用宽带无需公网 IP、无需端口映射。

## 适用场景

- 人在外面，想提前把日常挂上。
- 想隔一段时间看一眼游戏画面。
- 需要让家里人/室友代办，但不方便远程桌面。

不适用于：跨账号批量控制、需要实时帧级操作的场景。

## 链路

```
QQ 客户端 → QQ 开放平台 → wss 网关（BetterGI 主动连出去）
                              ↓
                        QqBotGatewayClient（长连接 + 心跳 + 重连）
                              ↓
                     RemoteTaskCommandHandler（指令 → 独立任务）
                              ↓
                     SoloTaskExecutionService（与界面里的独立任务同一套状态机）
                              ↓
        任务结束事件 → 失败才截图（GameScreenshot 同源）→ REST 上传 → 回到原会话
```

关键设计取舍：

- **走 WebSocket 而不是 Webhook**：Webhook 要求公网可达的 HTTPS 地址，家用环境做不到。
- **复用独立任务框架**：远程下发和界面点「开始」走同一条执行路径，任务清单、参数默认值、互斥锁都一致，不存在两套行为。
- **只在主实例启动**：桌面分身多开时，同一 AppID 的多条会话会互相顶号，非 Primary 实例直接跳过。
- **凭证可回落**：远程任务的 AppID/AppSecret 留空时复用「通知设置」里已绑定的 QQ 凭证，避免同一份密钥填两遍。

## 开放平台配置

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人应用，拿到 AppID 与 AppSecret。
2. **开发设置 → IP 白名单**：留空（本链路没有固定出口 IP）。
3. **开发设置 → 事件订阅**：勾选「群聊 @机器人消息」与「单聊消息」。
   - 对应的 intents 是 `1 << 25`（`GROUP_AND_C2C_EVENT`）。
   - 频道消息（`1 << 9`）**不要勾**：没开通却写进 intents，网关会以 `op=9` / 关闭码 4014 整体拒绝，连私聊也一起失效。
4. **沙箱配置**：开发阶段机器人只能收到「沙箱成员」的消息，把自己和需要下发的同事加进沙箱成员列表。
5. 上线前需要提交审核；审核通过前，非沙箱成员发消息不会产生事件。

## BetterGI 配置

「设置 → 通用 → 远程任务（QQ 机器人）」：

| 项 | 说明 |
| --- | --- |
| 启用远程任务 | 打开后重启 BetterGI 生效 |
| 接受群聊指令 | 关闭后只接受私聊 |
| AppID / AppSecret | 留空则复用通知设置里的 QQ 凭证 |
| 没跑成时回传画面 | 失败 / 取消才截；成功只发结果与告警，关闭则全都不发 |
| 截图最长边 / 质量 | 默认 1280 / 80，一张截图约 100–200 KB |
| 允许的 OpenID | 逗号或换行分隔；**留空时第一个发消息的人自动成为所有者** |

首次使用建议：先在私聊里发一句「帮助」，让机器人把你的 OpenID 自动写进白名单，再到设置页确认那一串数字已经填上。群聊里同一个人的 `member_openid` 与私聊的 `openid` 不同，两边都发一次即可各自绑定。

## 指令解析：规则优先，大模型兜底

先跑 `RemoteTaskCommandParser`（纯函数，无网络）：任务标识、显示名、中文别名、内置指令，四种说法都能命中。命中就立刻执行，一次往返都不花。

没命中时把整句交给「设置 → AI」里配置好的模型，要求它只输出一个 JSON：

```json
{"intent":"run","task_id":"auto_domain","say":"想刷秘境，这就开"}
```

模型返回的任务标识必须出现在注册表里，否则整条结果作废、退回规则结论——不给模型编造标识的机会。模型不可用、超时（20 秒）或输出不合规时同样退回规则，聊天链路不依赖大模型可用性。

`intent: chat` 用于与下发无关的话或信息不足的情况（例如只说「重新执行」但说不清是哪个任务），由模型直接回答。

## 后台保活

「设置 → 通用 → 远程任务」里的**关闭窗口后继续在后台运行**打开后，点关闭只做 `Hide()`，进程、QQ 长连接、任务调度全部保留；真正退出走托盘菜单的「退出」（`MainWindow.RequestExit()` 置位后放行 `Closing`）。

两个约束：

- 只在主实例生效。分身进程不常驻，否则关掉主程序后托盘会残留多个进程，还各自抢着连同一个 AppID。
- 托盘图标与保活联动：`EffectiveShowTrayIcon = ShowTrayIcon || KeepAliveInTray`。保活开着却把图标藏了，就会出现「程序在后台跑但没有入口」。

## 指令

| 指令 | 作用 |
| --- | --- |
| `一条龙` / `日常` | 运行一条龙 |
| `清体力` / `体力` / `树脂` | 体力计划 |
| `秘境` / `首领` / `地脉` | 对应的独立任务 |
| `领邮件` / `纪行` / `尘歌壶` | 日常奖励类 |
| `运行 <任务名>` | 通用前缀，支持任意已注册任务 |
| `状态` | 当前任务与状态 |
| `截图` | 回传一张当前画面（截图器没开会自动启动） |
| `更新` | 检查并下载新版，逐文件校验；有增量包才走热更新 |
| `重启更新` | 应用已下载的更新：退出进程、替换文件、自己回来 |
| `绑定米游社` | 私聊扫码绑定米游社账号，之后不开游戏也能查树脂 |
| `停止` | 中断当前任务 |
| `任务` | 列出全部可下发的任务 |

任务名匹配对空格和标点不敏感，「运行 清体力」「帮我跑个秘境」都能识别。

## 米游社扫码绑定

一开始的写法是让用户自己去浏览器 F12 抄 Cookie 再粘进设置页。实际用下来这条路走不通：多数人不知道 F12 是什么，抄漏一个 `ltoken_v2` 就只看到一句 retcode 5003；在 QQ 里问「怎么绑定米游社」，机器人也答不上来——它根本不知道有这回事。

现在改成官方扫码通道，人和机器人都只需要一句「绑定米游社」：

```
生成二维码（passport-api）→ 米游社 App 扫码 → 手机点「确认登录」
   → 再发一句「绑定米游社」→ 轮询到 Confirmed，Set-Cookie 里就是登录态
   → 查账号下的原神角色 → 只有一个就直接记下 UID，多个就回序号让用户选
```

几个必须守住的点：

- **只在私聊**。二维码谁扫到都算数，发在群里等于把账号递出去；登录态又是全局配置，第二个人再绑会覆盖前一个人。群聊里发这条指令直接拒绝并说明原因。
- **两步而不是一步**。机器人没有主动推送通道，一次回复里也只能带一条图文；先回二维码，用户扫完再发一句触发轮询，比让请求挂三分钟等扫码稳。
- **不落盘票据**。二维码三分钟过期，重启后本来就该重扫；绑定会话只存在内存里。
- **多角色要问**。米游社一个账号可能挂多个原神号，扫完把角色列出来让用户回「绑定米游社 2」，选角色的窗口是 5 分钟。
- **令牌不进日志**。日志只写「已保存登录态，米游社账号 xxx（N 个字段）」，Cookie 原文只在配置里。

### Set-Cookie 一个字段都不能挑

米游社的 v2 登录态不是自包含的：`ltoken_v2` 要靠配对的 `ltmid_v2` 才能定位到签发它的那次会话。**缺 mid，令牌再新也会被判未登录**（`retcode 10001`，message 是 `Please login`）。

7.7.2 及以前的 `MysCookieBuilder` 按一份十几个字段的白名单挑 Set-Cookie，把 `ltmid_v2`、`account_mid_v2` 直接丢了。表现是：扫码绑定显示「绑定好了」，一查树脂永远 `Please login`；角色列表接口也回 `-100`，用户只能手填 UID。排查时看 retcode 只会得出「Cookie 过期」的结论，于是反复重扫，问题照旧——这是最容易走偏的一类故障。

现在的规矩：

| 处理 | 做法 |
|---|---|
| Set-Cookie | 原样全收，只剔除 Path/Expires 这类属性；值为 `deleted` 时删掉同名字段 |
| 新旧名字 | ID 类（`ltuid`/`mid`/`account_id`）双向补齐，两边都留 |
| 令牌类 | **不互抄**。`ltoken_v2` 的值以 `v2_` 开头，塞进 `ltoken` 会被当成格式错误的 v1 令牌 |
| 拼装顺序 | 账号在前、令牌在后，方便对着开发者工具核对 |
| 日志 | 只打字段名，不打值 |

同时角色列表改用 `getGameRecordCard`（与实时便笺同源、同一套 v2 登录态）作为首选，老的 `getUserGameRolesByCookie` 只保底——后者只认 v1 `cookie_token`，扫码得到的新登录态基本查不出来。

### 绑定后立刻自检

扫码只证明「拿到了 Cookie」，服务端认不认是另一回事。所以绑定完成的最后一步是**真的查一次便笺**：

- 查通了才回「绑定好了……现在树脂 17/200」；
- 查不通就回「绑定好了，但登录态没能通过实测：<具体 retcode 与原因>」，并让用户重扫一次。

这条自检是 7.7.2「绑定成功但永远 Please login」的直接产物——没有它，用户要等到下次问体力才发现这份登录态是废的，中间那句「绑定好了」就是误导。

桌面端「设置 → 通用 → 远程任务 → 米游社 Cookie / UID」旁边也有「扫码绑定米游社」按钮，走同一个服务，少一次抄 Cookie。手填 Cookie 的入口保留，老用户和想用自己浏览器登录态的人仍然可以贴。

绑定失败时的处理：二维码过期就换一张；`5003` 说明登录态不完整，重新扫；账号下查不到角色（通行证没同步）则只存登录态，提示用户手填 UID。

## 平台限制

- **被动回复窗口**：收到消息后 5 分钟内、同一 `msg_id` 最多回复 5 条。任务跑超过 5 分钟时，结束通知会超出窗口，此时自动降级为主动消息。
- **主动消息额度**：C2C 与群聊的主动推送有每日/每月配额，未申请时可能失败。失败只记录日志，不影响任务本身。
- **图片**：`file_data` 直传，单张建议 1 MB 以内；压缩后仍超限会降级为纯文本。
- **频率**：同一会话串行处理，连续快速发多条指令会排队执行。

## 故障排查

| 现象 | 原因 |
| --- | --- |
| 日志出现「鉴权失败（第 1 次）」并重试 | AppID/AppSecret 不对，或开放平台没开事件订阅 |
| 一次就报「鉴权连续失败，已停止重连」 | intents 未授权，检查是不是勾了频道消息 |
| 私聊机器人完全没反应 | 沙箱期不在沙箱成员列表，或事件订阅没开「单聊消息」 |
| 回复「这个账号没有远程控制权限」 | 白名单已填但没包含当前 OpenID，按提示把 OpenID 加进去 |
| 截图失败 | 游戏没开、窗口被最小化到托盘、或截图器启动失败 |
| 任务没开始 | 已有任务在跑（独立任务互斥），回复里会说明当前在跑什么 |
| 发「绑定米游社」被拒绝 | 在群里发的；绑定只在私聊做 |
| 扫码后仍提示「还没扫到」 | 手机上只扫了没点「确认登录」；或二维码已过三分钟，再发一次换一张 |
| 绑定成功但查树脂仍报 5003 | 登录态不完整（少见），重新扫一次；实在不行改回手填 Cookie |
