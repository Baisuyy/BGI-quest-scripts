# 原神全主线任务解析

> 数据源：`AnimeGameData`（CNRELWin 7.2.0 / R49086080） · 解析对象：`CHAPTER_STYLE_TYPE_AQ` 全部章节
> 规模：**53 个章节 / 261 个任务 / 4,154 个子任务 / 2,452 个坐标点**

---

## 一、分类体系

原神主线的层级不是「任务→步骤」两层，而是四层。本次解析严格按游戏内配置还原：

| 层级 | 字段来源 | 数量 | 说明 |
|---|---|---|---|
| 篇章 | `ChapterConfig.chapterNum` | 9 | 序章、第一章…第七章、空月之歌，间章单列 |
| 地区 | `chapterIcon` + `cityId` | 9 | 蒙德/璃月/稻妻/须弥/枫丹/纳塔/挪德卡莱/至冬/旅人章 |
| 幕（章节） | `ChapterConfig` | 53 | 每一幕一个独立章节 ID，如 1001 |
| 任务 | `Quest.chapterId` | 261 | 含隐藏任务 23 个 |
| 子任务/步骤 | `Quest.subQuests` | 4,154 | 真正推动流程的最小单元 |

**几个容易踩的坑：**

- 任务的 `type` 字段（AQ/MQ/LQ）**不能**用来判断主线。璃月前三幕的任务是 `MQ`，若按 `type==AQ` 筛会整段丢失。正确做法是看 `chapterId` 是否落在 AQ 章节里。
- 章节名和幕名不在 `TextMapCHS`，而在 `TextMap_MediumCHS`；任务标题和步骤描述反过来只在 `TextMapCHS`。两张表必须合并。
- 任务文件名不等于任务 ID，但 `BinOutput/Quest/<id>.json` 恰好是 ID 命名，可直接索引。
- 同一幕内的任务顺序无法靠 ID 得到，必须用 `MainQuestFmtQuestRelate` 的前置关系做拓扑排序。

### 5.1 坐标覆盖断崖：自动化只能从第四章做起

把每一幕的坐标点除以子任务数，能看到一条非常陡的分界线：

| 第七章 | 537 | 505 | 94% | 基本完整 |

原因在数据结构本身：老任务（1.x–3.x）的 `subQuests[].guide` 大多只有命名点位（如 `Q100001Player`），

这意味着**任何基于坐标的主线自动跑图方案，在第三章及以前都拿不到足够的锚点**，只能靠对话跳过 + 手动移动。
