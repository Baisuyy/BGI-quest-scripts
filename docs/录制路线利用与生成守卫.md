# 录制路线怎么用：可信边、实测锚点、生成守卫

这次动了两类数据：BGI 客户端里**真人录制的 343 段路线**，以及解包出来的**每步完成条件**。
先说结论，再说依据。

## 结论

| 想做的事 | 结果 | 原因 |
|---|---|---|
| 用录制路线替换任务路线的几何 | **做不到，0 段** | 270 段里 228 段离最近的录制点超过 1 km，样本不在同一片区域 |
| 用录制路线给路网当「可信边」 | **做了，709 条边 / 28 km** | 录制边占 Teyvat 路网总长 45%，A* 优先走它们 |
| 用录制记录定传送锚点 | **做了，38 段有实测锚点** | 每条录制路线都记着玩家从哪个锚点落地 |
| 生成前拦住不该有路线的步骤 | **做了，5336 生成 / 18790 拦下** | 解包的 `finishCond` 能说明每步靠什么完成 |
| 校验现有 270 段路线有没有踩线 | **270 段全部合规，0 违规** | 现有路线确实只配给了跑图步骤 |

## 一、数据盘得清

客户端 `GameTask/` 下 718 个 json，但不是都能用：

| 类型 | 数量 | 能不能用 |
|---|---:|---|
| 可行走路线（≥2 个 path 点） | 343 段 / 1,321 点 | 能，进路网 |
| 只有「锚点 → 终点」（地脉花采集） | 50 条 | 能，做实测锚点表（其中 47 条是 Teyvat） |
| 只有 1 个 target 点（战斗后快速前往的落点） | 286 个 | 不能，没有路径 |
| 无 positions / 解析失败 | 39 个 | 不能 |

坐标约定一致：`x = 游戏 X`、`y = 游戏 Z`，与任务 guide 的 `(X, Y高度, Z)` 不同，中间那个高度不写进路线。

## 二、可信边：让 A\* 优先走真人走过的路

`tools/pathing/build_graph.py` 现在合并两个来源，并给每条边打 `origin`：

| origin | 来源 | A\* 代价 |
|---|---|---|
| 1 | 官方录制路线走过 | 原价 |
| 0 | 只有脚本生成的直线 | ×1.35 |

合并后 Teyvat 规模从 3,898 节点 / 4,246 边，涨到 **4,816 节点 / 4,955 边（其中 709 条录制边）**。
录制边的长度占 45%——数量不多，但都是长段，正好补上「跨山谷怎么绕」这类信息。

代价是连通分量从 52 涨到 271：录制路线各连各的，不构成一张大网。主分量仍只覆盖 20.8% 的节点，
所以**长距离仍然必须靠传送**，路网只能解决「落地之后这几百米怎么走」。

实测（主分量内两点）：

```
直线 2351m，沿路网 2578m，绕行系数 1.10
路网点 179 个 → 简化后 70 点
```

## 三、实测锚点：解决「传送落地在几百米外」

`genshin.tp(x, y)` 只给目标坐标，锚点是 BGI 按最近挑的。挑到 963m 外的七天神像，
传送完就得横穿山地——看起来像「传送异常」，其实是选点问题。

`tools/pathing/anchor_plan.py` 用 301 条录制记录（锚点坐标 + 目标坐标）反查：目标点 300m 内有录制记录的，
直接采用真人用过的锚点。270 段的结果：

| 结论 | 段数 | 含义 |
|---|---:|---|
| recorded | 38 | 有录制记录，按记录里的锚点走 |
| nearby | 216 | tp.json 有 150m 内锚点，正常 |
| walk | 52 | 落地后要走 150–500m |
| far | 1 | 500–1500m |
| none | 1 | > 1500m，传送不可用 |

`far` 和 `none` 只有两段，正是之前手工查出来的那两段：

| 段 | 首点 | 最近锚点 | 距离 |
|---|---|---|---|
| 7030-如同消融的积雪 / 03 | 8789,2919 | 传送锚点 | 2920m |
| 7030-如同消融的积雪 / 02 | 9329,4821 | 七天神像-冰 | 963m |

这次是独立数据复现了同一个结论：那一片（雪桦车站 → 贝洛沃迪）在官方录制库里也完全空白，
不是脚本写错，是确实没有可用锚点。段 2、3 默认跳过是对的。

38 段命中里比较典型的几条：

| 段 | 目标点 | 真人用的锚点 | 偏差 |
|---|---|---|---:|
| 7031-迈向未来的一步 / 02 | 262,332 | 174,390（璃月4-璃月港-5） | 26m |
| 7031-迈向未来的一步 / 03 | 307,550 | 341,548（璃月4-璃月港-6） | 32m |
| 6034-幽暗时分 / 05 | 92,2970 | 266,2915（蒙德4-风龙废墟-3） | 62m |
| 7012-沉寂之地的枪声 / 02 | 7667,7746 | 7678,7727（至冬2-凝露镇-1） | 142m |

## 四、失败的那条路，也写清楚

`tools/pathing/optimize_routes.py` 本来打算做几何替换：在「录制边优先」的路网上重算每段，
通过就写回。判据定得很严（吸附 ≤ 60m、长度 0.60–1.30 倍、偏移 ≥ 25m、录制边占比 ≥ 50%、
离录制线至少近 20m），结果是 **0 段**。

不是算法不行，是样本不在场：

| 离最近录制点 | 段数 |
|---|---:|
| ≤ 100m | 2 |
| ≤ 200m | 18 |
| ≤ 500m | 32 |
| ≤ 1000m | 42 |
| > 1000m | 228 |

录制路线集中在 Boss 点和地脉花采集点，任务路线是剧情点，两者在地图上各占一片。
早期版本还踩过一个坑：采集环线（首末重合，如 5011/02 的 289 点绕圈）会被 A\* 算成 0 长度，
现在单独识别成 `loop`，共 17 段。

所以这个工具现在的定位是**体检报告**，不是改写器：它逐段给出「离录制线多远、能不能被路网覆盖、
为什么不动」，`--apply` 保留但默认不用，等真的录到主线路线再开。

## 五、生成守卫：从源头堵住无效路线

`tools/quest/guard_generator.py` 读 `data/quest_steps.json`（每步的 kind 与 flags），按顺序判定：

| 条件 | 结论 | 理由 |
|---|---|---|
| 已确认的独立地图 | 生成 | 目前只有 `20378 → TempleOfSpace`，有自己的锚点表 |
| kind != path | 不生成 | 对话、剧情、计数等没有可走目标 |
| 无坐标 | 不生成 | 没有目标点 |
| `local_coords` | 不生成 | 局部坐标交给大地图会跑到几公里外 |
| `requires_unlock` | 待解锁 | 没开传送点就是黑雾，生成也跑不了 |
| scene 3 | 生成 | 提瓦特 |
| 其余 scene，坐标在原点 1500m 内 | 不生成 | 室内/独立地图的局部坐标，地图名未知 |
| 其余 scene，坐标是世界量级 | 生成（Teyvat） | `20276` 试验设计局、`20372` 曙光车站这类 |

最后一条是踩坑加的：`20276` 潜入试验设计局 `3094,215,9513`、`20372` 曙光车站 `8478,224,7792`
挂在非 3 的 scene 上，用的却是标准世界坐标。早先按「scene != 3 一律拦」，把 100 段合法路线误判成违规。

结果：

| 指标 | 数值 |
|---|---:|
| 全部步骤 | 24,126 |
| 可生成 | **5,336** |
| 拦下 | 18,790 |
| 其中「不是跑图步骤」 | 18,788 |
| 其中局部坐标 / 待解锁 | 1 / 1 |
| 现有 270 段检查 | 合规 270 / 违规 0 / 未匹配 0 |

现有路线 0 违规这件事本身有价值：它证明之前判断的「脚本大量缺失」不是生成器漏了，
而是 78% 的步骤本来就不需要路线。

## 六、复现

```bash
# 官方录制路线 → data/official_routes.json（BGI 更新后重跑）
python3 tools/pathing/official_import.py

# 建路网（含录制边，带 origin 标记）
python3 tools/pathing/build_graph.py

# 逐段体检（默认只报告）
python3 tools/pathing/optimize_routes.py

# 传送锚点核对
python3 tools/pathing/anchor_plan.py

# 生成计划 + 现有路线检查
python3 tools/quest/guard_generator.py --plan --check
```

产物：`data/official_routes.json`、`data/anchor_plan.json`、`data/generation_plan.json`，
报告：`docs/路线优化报告.md`、`docs/传送锚点核对.md`、`docs/生成器守卫报告.md`。

## 七、仍然缺的

1. **主线路线没有录制样本**。要真正修掉穿山，只能靠实跑录制，或者用地形数据（高度图 + 可通行栅格）算，
   当前解包里没有可用的地形数据。
2. **室内不可寻路**。143 个场景是局部坐标，只能场景内小移动；这些步骤应当在脚本里等剧情推进，
   而不是生成路线。
3. **高度仍然没有**。录制器与路网都是二维；官方录制里 `fly` 段中位只有 19m，是「跳一下滑过去」，
   不足以还原长距离滑翔的起降高度。
