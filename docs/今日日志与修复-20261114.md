### 1. 剧情脚本「错位」

7030「如同消融的积雪」的步骤坐标（第七章第五幕，实际在挪德卡莱）：

```
 1 前往至冬堡      (9654,6607) → 最近锚点 赝月的研究所 245m
 4 前往雪桦车站     (9329,4821) → 新月神像 340m
 9 乘坐火车…        (9647,4274) → 传送锚点 680m
12 击败涌出的魔物    (8789,2919) → 传送锚点 405m
```

坐标本身对得上（整幕都在挪德卡莱），错的是**分段**：`前往至冬堡` 这一步只有一个点，
生成器仍把它做成一段「路线」，运行时 `pathingScript` 朝那个点直冲，落点就是征讨领域门口。
用户看到「前往至冬堡」却站在「赝月的研究所」，自然会判断为错位。

全仓统计（`tools/quest/script_readiness.py`）：

| 指标 | 数值 |
| --- | --- |
| 脚本 | 100 |
| 路线段 | 291 |
| 单点/空段 | 116 |
| 可用 / 部分可用 / 跑不了 | 37 / 52 / 11 |

也就是说 40% 的段其实是「任务提示坐标」，不是路线。这是系统性问题，不是 7030 一个脚本的偶发。

### 2. AI 弹窗

```
[22:43:36] run_task one_dragon → 已下发
[22:43:36] "一条龙"任务失败：未找到一条龙配置「默认配置」
[22:43:40] list_tasks → 共 26 个内置任务。
[22:43:42] 达到步数上限 · 10 步 / 9 请求 / 10.6s
```

三个问题：

- 预算 10 步，光「看不明白 → 再查一次」就用完了；
- `run_task` 不看用户有没有建配置，直接下发，失败还要等下一轮 `task_status` 才知道；
- `list_tasks` 返回了完整清单，但日志只留首行「共 26 个内置任务。」，事后完全看不出模型看到了什么。

### 3. 焦点被自家窗口占住（最严重）

```
22:44:32.805 点击候选列表："传送锚点"
22:44:32.917 当前获取焦点的窗口为: BetterGI，不是原神，暂停
...（连续 13 次，每秒一条）
22:44:45.124 地图候选点击 #1 未生效：候选列表仍然存在
22:44:57.105 点击传送点后未出现交互面板，可能是传送点未激活
```

链路很清楚：面板是 `Topmost` 窗口，发完消息焦点还在输入框 → 游戏失焦 → 任务侧的焦点检查按
「用户切走了」处理，直接抛 `RetryException` 暂停 → 传送点击全打在暂停里 → 候选列表超时。

真正的错在于：**检查逻辑分不清「用户切走了」和「BGI 自己的窗口挡着」**。

## 二、改了什么

### 焦点（对应反馈 3）

1. `GameTask/Common/GameRuntimeExtensions.cs`
   - 新增 `IsOwnWindowForeground()`：前台窗口 PID 等于本进程即认定为自家窗口。
   - `RestoreFocusOnLostEnabled=false` 时，若前台是自家窗口，自动 `FocusWindow(游戏句柄)` 并继续，
     最多 3 次（`MaxOwnWindowReclaims`）；用户真的在操作界面时不无限抢。
   - 不再每秒刷同一条 WRN。
2. `View/Windows/AgentPanelWindow.xaml.cs`
   - 发送后立刻 `ReturnFocusToGame()`：面板留在原地显示进度，但焦点还给游戏。

### AI 下发（对应反馈 2）

3. `Core/Ai/AgentTasks.cs`
   - `run_task`（`wait=false`）下发后观察 1.2 秒；若已经停止且带错误，直接把原因写进工具结果，
     并提示「看参数与依赖，不要原样重试」。
4. `Core/Ai/LocalAgent.cs`
   - 系统提示补两条：配置缺失时说明缺什么 / 立即失败最多再试一次。
5. `Core/Config/AiConfig.cs`
   - `AgentMaxSteps` 默认 10 → 16（实测一次完整「查—确认—下发—核实」要 5~8 步）。

### 剧情脚本（对应反馈 1）

6. 全部 100 份 `main.js` 批量加了单点段保护：

   ```js
   if (!data.positions || data.positions.length < 2) {
       bad++;
       log.warn('  段 ' + seg.seq + ' 只有 ' + data.positions.length + ' 个点，是任务提示点而非路线，已跳过');
       continue;
   }
   ```

   单点段不再传送、不再直冲，只留一条明确警告。`node --check` 100/100 通过。
7. 新增 `tools/quest/script_readiness.py`，产出 `docs/脚本可跑性报告.md`：
   哪些任务能跑、哪些只是「提示点集合」、哪些整份都跑不了（11 个）。

### 日志（对应反馈 4）

8. `App.xaml.cs`
   - 模板改为一行一条：`[时间] [级别] [实例] 来源 | 消息`，异常另起。
   - 接入 `RepeatSuppressorSink`：连续相同的行只留第一条，出现不同内容时补一行「上一条重复 N 次，已省略」。

## 三、远程任务下发（TODO，未实现）

目标：QQ / 微信发一句话，BGI 在自己机器上执行。

可行形态（不改客户端网络暴露面）：

```
手机 QQ/微信 → 机器人（OneBot / 企业微信 webhook）
            → 中转服务（自己的 VPS 或 Cloudflare Worker）
            → BGI 长轮询（HTTP GET /tasks?since=...）拉取
            → 本地 AgentTasks 执行 run_task / run_script
            → 结果回写中转 → 机器人回消息
```

要点：

- **不做端口映射**。BGI 侧只出站长轮询，避免家里路由器暴露。
- **鉴权**：一次性配对码换设备 token，token 存本地配置；中转只认 token，不认昵称。
- **白名单**：只接受 `list_tasks` / `run_task` / `run_script` / `stop_task` / `task_status`，不接受任意代码。
- **二次确认**：`run_script` 这类可能改文件的动作，回一条「回复 1 确认」。
- **幂等**：每条指令带 message id，重复投递只执行一次。

现有代码已经具备条件：`AgentTasks` 的工具表就是天然的白名单，`execution.StartAsync` 是唯一入口，
只需加一个「远程指令源」把消息转成同样的 `JsonObject` 调用。
