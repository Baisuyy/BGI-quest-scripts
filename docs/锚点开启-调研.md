# 锚点开启：能不能做，卡在哪

一句话结论：**BGI 生态里没有现成的「自动开锚点」脚本**，也没有公开的「锚点 → BGI 游戏坐标」表；能做，但要先补一层坐标标定，再解决「未解锁不能传送」的走位问题。

## 一、现成方案排查

| 来源 | 结果 |
|---|---|
| BGI 官方文档 / 功能列表 | 只有「快速传送」：在地图上点锚点后自动确认，仍需人点 |
| 官方脚本仓库 `babalae/bettergi-script` | 只有地图追踪路线（采集、锄地），无锚点相关 |
| 社区脚本仓库、GitHub 搜索 | 未找到 BGI 版锚点开启脚本 |
| `Sam5440/Genshin_Impact_Teleport` | 有全量锚点**游戏坐标**，但数据停在 2.8，无枫丹之后 |
| `zheng327/Genshin_TP_Json` | 是外部 TP 工具用的坐标文件，格式不通用 |
| 米游社大地图接口 | 有锚点/神像点位，但坐标是**地图平面坐标**，不是游戏坐标 |

## 二、三个卡点

**1. 坐标系不通。** 米游社 `x_pos / y_pos` 与 BGI 用的游戏坐标不是同一套：同一个锚点在两套坐标里差着缩放和平移，直接塞给 `genshin.tp()` 会传到几百米外。要换算得先做一次标定。

**2. 没解锁的锚点不能传送。** `genshin.tp(x, y)` 的前提是那个位置有已激活的锚点。未解锁的锚点在地图上没有图标，点不到，只能从最近的已解锁锚点**走过去**。

**3. BGI 不会野外寻路。** 地图追踪是沿录制好的路线走，不是 A*。锚点大多在山上、崖边、洞里，直线插值过去基本会卡住，靠 `PathExecutor` 脱困也只是原地挣扎。

## 三、已经抓到的数据

`tools/anchors/fetch_anchors.py` 从米游社拿到了 745 条点位（神像 64、锚点 681）：

```bash
python3 tools/anchors/fetch_anchors.py   # 输出 tools/anchors/anchors_raw.json（83 KB）
```

要注意这是**玩家在地图上打的标记集合**，不是官方点位表：同一锚点可能被多人重复标记，`author_name` 都是玩家名。位置是准的（玩家点在图标上），但：

- 需要去重（按 30 米内聚类）
- 坐标还是米游社体系，不能直接给 BGI

## 四、三条可走的路

**A. 先做坐标标定（半天工作量，之后才有得谈）**

写一个标定脚本：读 `anchors_raw.json`，把米游社坐标按猜测的仿射变换转成游戏坐标，`genshin.tp` 过去，用 `genshin.GetPosition()` 记录落点，反推真实锚点坐标，迭代几轮收敛。跑一次约 20–40 分钟，全程在游戏里，需要人在旁边看着。

标定完能拿到「锚点 → 游戏坐标」表，之后无论是做巡检还是走位都用得上。

**B. 只做已解锁巡检（1 小时，收益立竿见影）**

标定之后，对每个锚点 `tp` 一次：成功 = 已解锁，失败 = 未解锁。输出一份「哪些锚点没开」的清单，按区域分组。不开的照旧手动去开，但不用满地图找。

**C. 按区域录制路线（最可靠，最费人）**

每个未解锁锚点，从最近已解锁锚点录一条路线，脚本只负责串联。跟现有 100 个任务脚本是同一套做法，稳，但一个锚点一条路线，全图几百条，不是脚本能自动生成的。
