# 路网与导航：让路线不再两点直连

## 问题

现有 270 段路线的路点，两点之间是**直线走**。平地上没问题，遇到山体、断崖、水域，角色会贴着障碍物硬顶，最后卡死。路线本身没有"怎么绕"的信息。

## 做法

把仓库里所有路线文件的点拼成一张图，查路时在图上走 A*，跟导航软件一个道理：**先上路，再走。**

```
route.py --from 起点 --to 终点
        │
        ├─ 吸附：找最近的网格节点（>300m 视为无路网覆盖，直接拒绝）
        ├─ A*：节点间沿已有路线的相邻关系走，代价是米数
        └─ 接驳：首尾各一段直线；中间沿别人走过的点
```

| 参数 | 值 | 说明 |
|---|---|---|
| 网格 | 15m | 同格的点合并，避免一条路被拆成几百个节点 |
| 边 | 同一文件内相邻路点 | 权重取实际距离，重复边保留最短 |
| 启发 | 到终点的直线距离 | 保证 A* 最优 |
| 简化 | Douglas-Peucker 2m | 导出前压点，不然一段路几百个坐标 |

当前规模：**291 段路线 / 9,434 个原始点 → 4,001 个网格节点 / 4,354 条边 / 53 个连通分量**。

实测一条至冬路线，直线 438m、沿路网 610m（1.39 倍），0.05 秒出结果。

## 用法

```bash
# 1. 建图（路线更新后重跑）
python3 tools/pathing/build_graph.py

# 2. 查路（只打印统计）
python3 tools/pathing/route.py --from 9560.3,-1240.7 --to 9211.3,-913.6

# 3. 导出可直接跑的路线
python3 tools/pathing/route.py --from 9560.3,-1240.7 --to 9211.3,-913.6 --out /tmp/route.json
```

`graph.json` 就是**留存的地图数据**：节点世界坐标 + 邻接表，332KB，纯 JSON，不依赖 BGI。

## 局限（都是真的，不绕）

1. **53 个连通分量**：各章节的路线彼此不连。跨区域必须靠传送锚点，路网不会把两个大陆连起来。
2. **只覆盖有人走过的地方**：新地图、黑雾区、冷门任务没有路网，`route.py` 会以退出码 2/3 明确拒绝，而不是给一条穿山的假路线。
3. **没有高度**：路网是二维的，上下层（洞穴、悬崖）会压在同一张图上。跨层的地方要靠路点自带的 `move_mode`（fly/climb）或人工补点。
4. **不替代实跑**：A* 只保证"沿着已知点走"，不保证这些点本身没被地形改过。生成完仍要跑一遍。
